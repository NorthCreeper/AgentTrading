# 全历史 TWAP 达标后反向结算：统计口径独立审阅

审阅时间：2026-10-23 香港时间。只读研究，不改变策略、账户或服务。

## 1. 当前策略的比较标准

- 协议 `ray-twap-calendar-onetap-v7`；偏离为 **当期 Chainlink BTC/USD 60 秒 TWAP − 该轮开盘 60 秒 TWAP / 官方 Price to Beat**。旧 Ray 的开盘 spot 不是本统计的参照。
- 香港时间 06:00 ≤ t < 12:00 门槛 40 美元，12:00 ≤ t < 22:00 门槛 60 美元，其余 80 美元。
- 当前日历 policy 有 **45** 个日期×时段单元，`admitted` 全为 false，实际全部继承 40 / 60 / 80。旧研究报告的 36 是旧口径，不能代替当前文件实测。
- 阈值等号算达标：`deviation >= T` 为 Up 达标；`deviation <= -T` 为 Down 达标。
- 主统计只检验 TWAP 条件，不附加盘口 80/20、买价 80–85 美分、余额、最小份额或仓位条件。当前主策略只在最后 120 秒开仓，故同时提供全 300 秒与最后 120 秒两张表，后者更接近当前可触发窗口。
- 市场区间 `[start,end)`；最后 120 秒区间 `[end−120000,end)`。边界 end 不作为新触发时刻，官方结果在 end 之后可用于结果核验。

## 2. “达标后反向结算”按盘口去重

先为每个盘口分别记录 Up 达标和 Down 达标。官方 winner 为 Up 时，只要该轮出现过 Down 达标即为反向结算盘口；winner 为 Down 时，只要曾出现 Up 达标即为反向结算盘口。

每个盘口在每个观察范围最多计一次。某轮两方向都曾达标，仍只计一个反向结算盘口，但保留双向穿越标记。逐轮报告应明确达标后失败的方向，并报告该失败方向累计 / 最长达标维持时间，避免把最终正确方向的时长加进去。

主表分母至少并列：完整有记录轮数、正确基准+官方标签可用轮数、曾达标轮数、反向结算轮数。反向 / 完整可用轮和反向 / 曾达标轮是不同问题，均可列出，不能混用。

## 3. 旧数据的使用方式

1. **历史事实描述主集**：该轮有足够完整的真实 60 秒 TWAP 路径、相匹配的已核验官方开盘 K 和官方结算 winner。官方 K 可以是事后获得，但须标注此集不是当时可实施的因果策略回放。这样可纳入换策略前的完整路径，不将旧 spot 误认 K。
2. **因果可用子集**：在首个达标报告被接收前，已经真实收到准确 opening 60s TWAP / 同轮官方 K；`opening.knownAt <= crossing.receivedAt`；同期源时钟及接收时钟可信。保留已知时点、收到时点和来源证据。
3. 缺正确 K、缺官方 winner、路径不完整或来源冲突分别列为未知 / 排除原因。不可把未知轮归为没达标，也不可只因旧策略没有下单而排除。
4. 历史策略版本只用于分层说明，统一以当前 v7 的正确 K 与门槛重算。旧盈亏、spot 方向、交易成交记录都不能替代路径或官方 winner。

## 4. 维持时间定义

推荐主口径为 **相邻真实 TWAP 报告支持的达标区间时长**：

- 报告按 source timestamp 排序；完全相同的报告去重。相同 source timestamp 存在不同 valueE18 时不得用数组顺序或更有利价格裁决，应隔离冲突轮 / 冲突时段。
- 对相邻真实报告 i,j，仅当 `0 < t[j]−t[i] <= 5000ms`，两端均为同一失败方向达标且阈值对应各端实际时段时，计入 `[t[i],t[j]]` 与目标观察窗口的交集长度。
- 两端状态不同的跨阈值区间不插值，实际穿越时刻保留为 `(previous.sourceAt,current.sourceAt]` 的夹界。`firstObservedAboveAt` 是首次观察到达标的报告时刻，不命名为真实首次穿越。
- 相邻间隔大于 5 秒、值冲突、无效窗口、时钟异常、记录断档都结束连续段，不把断档算作持续，也不自动把断档两侧合并为一段。
- `totalAboveMs` 为所有被支持达标区间长度之和；`longestAboveMs` 为最长连续段；`episodeCount` 为连续段数。单个孤立达标报告可构成发生事实，但没有正长度支持区间，时长为 0 且加 `isolated-only` 标记。
- 由于采样间仍可能短暂跌破阈值，上述数字是保守的采样支持口径，不能声称为不可反驳的连续物理时长下界或毫秒级真实持续时间。
- 另列首个达标报告至 end 的时间，但命名 `firstObservedAboveToRoundEndMs`，明确它包含后续低于阈值 / 反向 / 未知时间，**不是达标维持时间**。
- 首次回落阈值内、首次方向反转（越过 0）、首次反方向也达到阈值分别记首次被观察到的时刻；保留之前报告夹界。未观察到时为 null，不推成 end。
- 官方已结算的 `observedAt` 是核验可用时间，不是市场结束时刻；不能把结算查询延迟加到维持时间。

## 5. “完整”与缺口的呈现

- 不将第一条收到时间晚 1–2 秒判为全轮无效：Chainlink 官方说明报告传输通常会迟 1–2 秒，且窗口长度并不总为 1 秒。
- 可用每轮 60 个固定 5 秒槽有真实帧 + 首尾源边界误差 ≤5 秒等作采样完整的筛选；最后 120 秒对应 24 槽。这样也应报告真实帧数、去重 TWAP 报告数、首尾偏差、最大 source gap、coveredMs 和 unknownMs。
- **有帧记录完整不等于 TWAP 价格完整，也不等于双侧可执行盘口完整**。本轮偏离统计需要 TWAP 路径和官方标签，盘口记录覆盖可另列。双侧盘口新鲜 / 深度完整可作为严格子集，但不应无声把大部分历史删去。
- 不因当前策略会等 5 秒 / 订单要求新鲜度就将粗采样旧数据插成 1 秒；严格表需保留其真实间隔和精度。超过采样容忍的旧轮只进不完整附表。
- 主统计仅在被冻结的 cutoff 前已经结束的盘口；运行中的当前轮不当作最终结果，也不把其尚未来到的记录记为缺失。

## 6. 官方规则和本地标签验证

- Polymarket 官方市场页明确解析源为 Chainlink BTC/USD 60s TWAP；规则比较 `final >= opening` 归 Up，较低归 Down，等价时归 Up。
- Chainlink 官方说明 TWAP 是滚动窗口，锚定最新 observation；60s TWAP 不是整个五分钟平均。报告 source timestamp 与接收 timestamp 分开，窗口并不必然在整秒等间隔发布。
- 本地 `settlement.mjs::verifyResolution` 要求 slug/condition/token/start/end/rules 精确一致，Gamma closed+resolved、CLOB closed、唯一 winner，Gamma outcomePrices 和 CLOB token price/winner 一致，并以 eventMetadata.priceToBeat/finalPrice 方向交叉核验。`abs(final−opening)<1e−7` 因显示精度不足而被严格研究标签拒绝；这不是改变官方 tie→Up 规则。
- `payout-resolution.mjs::verifyPayoutResolution` 是独立的 paper 财务标签，允许 metadata 缺失 / 显示近似相等，但要求两官方 API 一致；metadata 若明确矛盾会拒绝。它不能单独补出正确 K。若用 payout winner 做本次事实标签，仍须另外拥有已核验官方 K 和匹配身份，并在结果中分 strict-research / canonical-payout-only 层。
