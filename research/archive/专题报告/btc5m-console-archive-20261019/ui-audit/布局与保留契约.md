# Ray 控制台重排审查

来源：只读检查原 `index.html`、`app.mjs`、`style.css`、`ray-entry-panel.mjs` 与 controller/server 接线。原页面选择器与对应源码摘要保存在 `selectors-and-wiring.json`：251 个 ID，无重复；列出 44 处事件绑定或批量选择器。此清单是重排前基准，不应被重排后的清单覆盖。

## 主台顺序

1. **总览**：实际运行状态、连接/时间/行情状态、启动/暂停/停止、当前 Ray 版本核对。保留实际错误出口，旧研究结果不能覆盖本版本运行核对。
2. **当前轮信号**：本轮时间与剩余秒数、真实开盘参考、TWAP 偏离及正在执行的门槛、六项准入条件、实际策略拒绝原因。日历或动态候选仍明确“观察、未采用”。
3. **预算与资金**：可用现金、可核实仓位净值、实际计划 2.5% 含费预算、允许 2.5%–10% 的金额范围、本轮 100 份已用与剩余；没有固定总成本上限。完整比例请求容不下时跳过，部分成交可以少于计划预算。
4. **订单与持仓**：主账户自动/手动来源、Ray 持仓合并与买入批次、待官方核实的结算队列、订单、日志。手动 One-Tap 继续按原退出规则管理，不能统一描述成全部持有到官方结算。
5. **历史研究档案**：可单独打开的区域，主台默认不展开。说明“旧研究、独立记录、未接入主策略”；不要把仍在采集的研究全部误写为“冻结”或“已停止”。

## 接线约束

- `app.render()` 对大量研究 ID 无条件写内容；同文档隐藏区域可继续安全更新。若拆成独立 HTML，不能直接沿用当前 app 而省略主台 ID。
- `#strategy-evolution` 仍有治理操作的 data 属性及委托处理器；迁移只是位置变化，不自动执行、开启或重置治理。
- 运行按钮、资金对话框、钱包只读区、订单表、日志筛选、卖出工具、原策略/运行参数对话框保留 ID。必须保留原禁用条件，重排不能解锁有持仓时的设置变更。
- 原 `#strategy` 下“总持仓成本预算限制”等固定上限旧说明需要改成当前 v5 规则。旧止损/持仓时长/P1 假设只留在对应档案中，不作为主策略规则。
- 抽屉/对话框新入口需可用键盘打开、Escape 关闭、关闭后焦点返回入口；链接 hash 应能重开档案并定位研究节点。不要给整个 live 区域设置高频 aria-live。
- 关闭档案不等于删除研究状态；不新增资金、不改变自动策略、不触碰历史账本。

## 新只读主策略面板接口

已单独实现 `dashboard/ray-console-panel.mjs` 和 `.test.mjs`，不包含任何下单或网络调用。

`rayConsoleView(state)` 返回：

`{visible,phase,reason,round,remaining,deviation,threshold,budget,range,quota,gates}`

每个 gate 是 `{key,title,status,detail}`，status 为 `pass/wait/fail/unknown`。`renderRayConsole(state,get)` 将其写入以下 ID：

`#ray-console`、`#ray-console-phase`、`#ray-console-reason`、`#ray-console-round`、`#ray-console-remaining`、`#ray-console-deviation`、`#ray-console-threshold`、`#ray-console-budget`、`#ray-console-range`、`#ray-console-quota`、`#ray-console-gates`。

条件卡 class 为 `ray-gate ray-console-gate`，`data-state` 与 `data-status` 都给出状态，便于现有样式接入。六项为：最后 120 秒、真实开盘、5 秒新鲜 TWAP 与偏离门槛、双侧盘口、80–85¢ 与对侧≤20¢、可信净值/现金/完整份额请求。

完整可入场状态需要当前后端决策、当前实际来源报价、所有条件通过且运行于自动模式；不依据缺失的 candidate 字段推断通过。参考价优先读取 `state.reference.price`，没有以新鲜 frame 替代实际已经过期的参考源。
