# BTC 5 分钟换轮异常调查与修复

检查日期：2026-10-21，时间均为香港时间（UTC+8）。本子任务只读检查运行中的模拟账户；源码修复由根任务统一登记并部署，本文不代表已部署。

## 结论

本次长时间停留在旧盘口的直接原因是 Gamma 的按 slug 查询路径连续返回 HTTP 404。请求已收到 HTTP 响应，TWAP/Chainlink 仍持续接收，因此证据不支持“整条网络断开”。故障覆盖已知当前轮及多条历史轮，不能解释为只有下一轮尚未发布。

旧轮 CLOB book 或结算查询没有串行阻塞发现下一轮：主行情和结算是独立轮询，日志显示 Gamma 请求目标随 UTC 时间切换了 23:25、23:30、23:35 各轮。23:30 轮的有效行情未获得；记录保留缺口，不能回填为完整观察。

旧错误记录只有来源域名、路径、耗时及 HTTP 404，没有响应头或正文。因此无法从历史证据继续区分 Gamma 后端、CDN、代理或其他访问路径故障，也不能证明备用入口在故障当时可用。

## 源码修复

1. 在 Gamma 主 `/markets/slug/{slug}` 明确返回 HTTP 404 时，尝试一次官方 `/markets?slug={slug}&limit=2`。备用结果必须是恰好一条记录且 slug 完全一致，随后继续原有 Gamma/CLOB 条件 ID、代币、时间、费用、盘口身份与报价时序校验。空数组、重复、错误轮、混入其他市场及异常结构均拒绝。
2. 主入口网络异常、403 或结构错误继续原样失败，不产生无界重试。主入口和备用入口都失败时保留两次请求证据，不产生新 frame，下一轮按真实 UTC slug 重新查找。
3. 一次 book HTTP/transport 失败不再销毁仍属当前轮的已验证市场身份，避免在可直接重试 book 时额外依赖 Gamma 重新发现。旧轮、结构校验失败仍清除缓存。
4. 定期元数据刷新失败可保留旧身份供诊断，但该次不发布 frame；缓存时间不会刷新，下一次仍需重新验证元数据。
5. 将元数据阶段错误归类为 market，将 book 阶段错误归类为 book。新增 requestUrl、httpStatus、failureType、requestStartedAt、failedAt、有限响应头及最多 512 字符正文；双入口失败保留 lookupRequests。只保留公开 Gamma slug/limit 查询参数，其他任意查询参数不进入诊断 URL。
6. 记录 `gammaLookupSource`、`gamma-market-fallback-used`、`gamma-market-lookup-failed`，保持原报价源时间、RTDS 开盘未知和缺口语义。

## 验证

62 项针对性回归全部通过，包括跨轮请求、过期旧市场、双入口失败、身份冲突、book 失败恢复、元数据更新失败不发布 frame、结构异常强制重验，以及原 RTDS/时钟/结算/策略观察测试。

实测当前官方主入口、备用入口、CLOB 市场资料和两侧 book 均返回 HTTP 200，主/备用标准化结果一致。另以模拟主入口 404 加真实官方备用响应验证完整后续身份校验；这属于当前可用性测试，不证明故障当时备用入口可用。

官方入口依据：[Polymarket List markets](https://docs.polymarket.com/api-reference/markets/list-markets)，以及[官方市场数据示例](https://github.com/Polymarket/agent-skills/blob/main/market-data.md)。
