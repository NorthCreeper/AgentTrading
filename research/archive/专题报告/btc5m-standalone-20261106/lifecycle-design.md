# BTC5m Windows 独立版生命周期设计

2026-11-06，只读审查。未修改生产源码、账户、配置或任务，未启动第二个后台，未接入真实钱包或交易。

## 当前实现与便携障碍

现有实现已经脱离聊天进程：Windows Task Scheduler → `headless-host.exe`（Windows Job Object，关闭时清整个子树）→ `supervisor.mjs` → `server.mjs`。Node为固定独立安装，服务有5秒心跳、失败重试及计划任务保活。

- `归档目录/Trade/service/service-config.json`写死Node、源码、数据的D盘绝对路径，固定端口18790、固定任务名；supervisor有固定长路径import和固定端口校验。复制service文件夹到别处不能直接运行。
- `打开BTC控制台.cmd` → `start-btc-console.ps1` → `打开BTC控制台.ps1`链路完整，均存在；并非缺失入口。但最终脚本依赖已经注册好的生产任务，不能在新电脑首次启动。
- `control-backend.ps1 Start`仅按managed+clock.ready判断API，未核对目标安装标识；同机多安装共享18790/固定任务名时，可能把另一套后台当自己的。
- `control-backend.ps1 Stop`先向API发stop，再禁用任务；API不可达会报错并保持原样，不谎报关闭成功。便携版必须另外区分“停止开仓/策略”和“关闭整套后台”。
- 现有`runtime-lease.mjs`在读取财务状态前抢loopback独占端口，端口按规范化目录+kind哈希；`process-runtime.mjs`还先绑定实际API端口，再初始化账户，防同目录双写及被占用端口。可复用。
- 目录租约不是跨副本账户租约：把同一账户复制到另一目录，再换API端口后，其租约不同；不得据此承诺任意副本不重复交易。迁移流程和默认停止状态必须明确。
- 现有进程有SIGINT/SIGTERM、IPC `btc5m-managed-shutdown`和父IPC断开处理；可先核对停止订单，再关闭服务和释放租约。Windows Job Object兜底杀子树。
- `state.json`缺失时初始化新账户；损坏或不兼容时不会被当成空账户。两代checkpoint带完整内容/金融字段校验，但当前boot未自动从checkpoint选择回滚；不能在打包说明中宣称自动无损修复。
- `run-intent.mjs`会在托管模式恢复保存的运行意图。生产迁移副本必须覆盖为停止并保留原始快照，不能将production running=true原样带到新机器。
- 源码还依赖旁路研究目录、模型、档案目录及登记；依赖清单由另一审计并行负责，不能只复制dashboard与Node就称完整。

## 推荐交付目录

```text
BTC5M-Standalone/
  Start.cmd               # ASCII入口，调用自身捆绑Node/CLI
  Stop.cmd                # 停止策略并关闭后台；不删除账户
  Status.cmd
  Backup.cmd
  Restore.cmd
  settings.json           # 相对路径、端口、paper/默认停止；无密钥
  installation.json       # schema/installationId/accountIdentity/数据版本
  app/                    # 原策略及依赖模块，保留lab/dashboard相对结构
  assets/                 # 固定模型、校准、日期资料等完整运行资源
  runtime/node.exe        # 已验证固定Node，含License与校验清单
  service/                # 便携CLI、headless host、supervisor、manifest
  data/                   # 此独立版账户/日志/官方结果/研究增量；首次为空
  logs/                   # host/supervisor/worker，轮转及上限
  backups/                # 完成备份；.partial不视为成功
  docs/                   # 使用、迁移、故障、权限边界
  package-manifest.json   # 相对路径、字节数、SHA256、版本
```

默认包交付全新且停止的模拟账户，不复制生产账本、running意图、钱包连接或浏览器存储。不修改/接管当前生产安装。另提供明确的账户迁移命令，保留历史时走校验导入。

## 必须完成的生命周期行为

### 启动

1. 所有路径以CLI文件位置解析，不依赖cwd、系统PATH、桌面用户名或D盘；配置只允许相对资源路径或明确独立数据根，不接受网页输入覆盖路径。
2. 验证捆绑Node版本/架构及SHA、资源manifest、配置schema与端口；失败显示可读错误和日志入口，禁止临时回退到聊天缓存Node。
3. 区分本安装已运行、其他BTC5m安装运行、普通进程占端口；仅本安装同数据目录/身份匹配时复用。冲突不杀进程、不改端口、不新建账户；显示现有服务信息及可选人工配置步骤。
4. 以已有headless host方式启动独立supervisor（隐藏窗口，不依赖PowerShell或ChatGPT进程持续存在）；Windows原生可执行文件启动不拼接跨shell命令。
5. 初始化前取得数据目录租约，建议额外用稳定accountIdentity取得本机账户租约，减少同账户复制到不同目录后误启。此额外租约也不能解决跨机器副本，需要迁移要求源端停止。
6. supervisor向worker传自身根路径、完整相对配置解析值及installationId；API返回installationId/数据身份，CLI必须核对才宣布就绪和打开浏览器。
7. 初次启动只启动控制台，模式paper且策略停止。后续同安装异常恢复可沿用已保存runIntent，但显式停止永远不被启动入口或保活任务推翻。
8. 离线/校时失败时显示启动或等待状态，不冒充健康、不自动放宽时钟和行情条件。保留日志，不清空账户。

### 停止与守护

- 控制台“停止”语义保持：核对模拟挂单，停止采集/策略，保留库存和待结算；它不等于关闭后台。
- `Stop.cmd`先验证本安装身份，再发stop并确认running=false/无活动执行，随后让本安装supervisor通过IPC关闭worker并停止守护。关闭浏览器不停止后台；启动器窗口退出不停止后台。
- 退出意图先持久保存，随后关闭；supervisor不可与显式stop竞速重新开worker。关闭整套后台后租约/API端口须释放，进程树中不得留孤儿。
- API不可达应报告未核实停止，不假装成功。若提供紧急关闭，必须只作用于本安装已验证的Job/进程身份（包括创建时间/可执行路径），禁止按“所有node.exe”或仅PID杀进程。
- 日志记录启动/停止原因、worker退出码及重试次数；持续失败进入明确blocked/backoff，不能无上限快速重启。
- Windows登录自启可选，不在解压或第一次启动时自动安装任务。使用installationId派生任务名；只修改属于本安装的任务；移动目录后明确重新登记。便携手动启动无需管理员。

### 一致备份

- 最小安全实现为离线备份：停止策略与整个worker/旁路writer，确认本安装租约释放后复制数据；只有POST stop不等于所有定时写入停止。
- 备份包括state、两代checkpoint、账户/交易日志、官方结果档案、开仓锁、实验/恢复证据、当前模型及源码版本/哈希和研究状态。不可只备份state.json或忽略到期未兑付库存。
- 输出先写唯一`.partial`目录/文件，流式复制并逐文件校验哈希、字节数。写manifest（UTC/HKT、版本、账户身份、文件边界、未知历史来源）后验证，再原子改名为完成备份。
- 现存多GB日志不可直接依赖Windows PowerShell `Compress-Archive`的单文件限制；优先捆绑明确支持ZIP64的实现，或用Node流式gzip逐文件+manifest的备份目录格式。不得先读整文件进内存。
- 空间不足、源文件变化、权限错误或哈希不符时，备份失败，保留.partial与失败信息，不显示成功、不删除源数据。是否恢复原后台必须明确；默认可保持停止，允许用户选择恢复原运行意图。
- UI“导出记录”继续是只读账本/研究导出，不应标成可恢复完整备份。

### 恢复与迁移

1. 先校验备份manifest/路径/哈希/版本，不向运行中账户覆盖。拒绝绝对路径、`..`、UNC、符号链接、NTFS替代流、Windows保留名称及解压越界。
2. 解包至本安装内独立staging目录。保存目前数据的完整回退副本，不递归删除未知路径。
3. 核对主状态和checkpoint、现金/费用/订单/持仓/库存成本、待结算、去重/开仓锁、session/experiment、研究状态及已存官方档案。未知事故区间继续保留；检查点是候选，不在没有重放核对时自动回滚资金。
4. 导入迁移账户先保留来源快照，再将导入运行意图转为停止/暂停，记录这项控制变更；财务和策略参数必须保持。浏览器钱包地址不随包迁移。
5. 原数据目录和staging在同卷原子切换；失败保留原数据。源端必须停止且完成导出，目标导入后由用户明确启动；不能默默同时运行两份同账本。
6. 主状态损坏但checkpoint有效时提供“候选检查/核对报告”并保持停止；全部损坏时保留原件和错误，禁止空初始化、补造历史或自动恢复交易。

## 验收场景

| 场景 | 必须看到的结果 |
|---|---|
| 路径含空格/中文/`&`，cwd任意 | Start/Status/Stop/Backup均只访问自身目录，浏览器打开自身API；命令不被shell拆分。 |
| 复制到非D盘且系统没有Node | 使用捆绑Node；无D:/Trade、TradeResearch或Codex缓存访问。 |
| 当前生产18790运行，尝试默认便携包 | 显示其他安装/端口冲突，生产PID/状态/订单不变，便携数据不初始化；不启动第二个自动实例。 |
| 两次并发Start同安装 | 只一个supervisor、一个writer；第二次连接本实例，无重复账户。 |
| 同账本复制目录并改端口 | 本机稳定账户租约阻止第二实例；跨机器迁移文档明确不能靠本机锁保障。 |
| 正常停止/只关闭浏览器/退出启动器 | Stop持久停止且无孤儿；关闭浏览器/启动器后后台继续；下一次Start尊重停止意图。 |
| worker被异常结束 | supervisor有限重试，恢复同账户，不改变现金、费用、订单、去重和实验。 |
| 无网络、可信UTC不可用 | 页面可辨识等待/错误，策略不新开仓，不绕过可信时钟。 |
| state JSON损坏 | 明确阻止自动运行，保留损坏原件；候选备份只核对，不静默归零。 |
| 有库存和待结算的备份恢复 | 与导出冻结点的现金、成本、订单、库存、队列、开仓锁、session/experiment逐项一致；目标保持停止。 |
| 大于2GB单日志/磁盘空间不足 | 流式处理可完成大文件；失败无“成功备份”，生产原件不变。 |
| 恶意/损坏备份或不兼容版本 | 导入前拒绝，目标数据及目录外文件不变。 |
| 把整个包再次移动 | 相对配置重新解析、模型/manifest通过；自启任务需明确重新登记，不遗留旧任务。 |
| 只读钱包 | 接入不改变paper或账户资金；窗口不要求私钥，真实下单能力仍未启用。 |

## 实施取舍

优先把现有金融、单实例、Job Object和运行意图实现封装成可搬迁发行版，避免为“独立”重写策略/账本。先交付完整停止状态的干净便携包、可验证备份恢复与迁移说明；登录自启、跨机器自动互斥和真实交易是不同能力，不能用打包完成代替其验收。
