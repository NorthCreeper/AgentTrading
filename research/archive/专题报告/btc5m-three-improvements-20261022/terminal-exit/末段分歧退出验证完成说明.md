三次退出对应的原始入场，按正确开盘 TWAP 核对全部不达当时原准入门槛。唯一仍合格的 v6 21:50 亏损没有形成足够持续的联合确认。因此上表不能证明修复基准后的新策略受益，更不能宣称策略已经盈利。样本跨 4 个历史日期，独立未看过的留出日期为 0；候选是在已复盘亏损后拟定，所有结果均为探索性历史检验。

三次延迟退出分别在信号后 2212、2017、1895 毫秒，实际可见买价仅 0.021、0.07、0.02；没有沿用更早的高报价。按源帧、源 spot、源开盘 TWAP 和官方标签的原始字节见证核对，并用独立逐档算式重算金额与费用，全部一致。三个退出的手续费分别为 $0.02878260、$0.41851488、$0.03862180。

其余 22 笔没有被删掉。无观测确认与数据缺失分别记录：例如 v6 的 22:00 盈利轮，末一分钟 57 帧全部未满足严格双侧完整盘口，不能把它说成“有完整证据证明不会误退”。历史无错误退出的数量只是本次严格可观测样本的结果。

## 固定候选

协议 `ray-terminal-book-spot-shadow-v1`：仅在末 60 秒、已校验正确 60 秒 TWAP 开盘基准、双 token 真实新鲜完整盘口可用时观察；持仓侧 ask ≤ 0.40，对侧 bid ≥ 0.60，且新鲜 Chainlink spot 相对正确开盘基准也指向对侧。必须至少 3 次源时间推进的独立观测，且本地观测与保守源时间均持续至少 2 秒。重复轮询同一快照不能积累确认。

这是一条待证伪的固定候选，不是已校准胜率。0.40/0.60、2 秒和 1 秒延迟均在配对重放前登记，没有按此处三笔结果调优。没有固定美元止损、60 秒最长持有或最后一分钟强制清仓；不改变仓位分配。

时钟未核实、双侧盘口缺失/过期/交叉、TWAP 或 spot 缺失/过期、盘口/condition/token 不匹配、开盘基准冲突、观测间隔超过 3 秒、断线或连接 epoch 改变，均清空确认。重启应使用新连接 epoch，不恢复旧确认计时。源时间仍标注 `unverified-server-timestamp`，原始文件内部一致不等于外部认证。

## 最终 API 与集成约定

`staged/dashboard/ray-terminal-risk.mjs` 不依赖项目模块，可以直接复制到生产 `dashboard/`。测试文件与其同目录。

```js
const { state, decision } = evaluateRayTerminalRisk({
  frame, trade, opening, spot, spotRows, now,
  prior, connectionEpoch, dataGap,
});
```

`trade` 至少包含 `slug / outcome / tokenId`；有 `market.conditionId` 时也会核对。`opening` 必须来自第一项修复后的正确开盘基准：`source=rtds-twap-sixty-opening|gamma-price-to-beat`，`basis=opening-60s-twap`，`windowSeconds=60`，`referenceAt===market.start`，身份精确匹配且当时已收到，无冲突。`spot` 使用原生 `rtds-chainlink-spot` 的 `value / referenceAt / knownAt / source`。`spotRows` 仅用于诊断终点代理，不参与触发。调用方应显式传入连接 epoch 与断线/缺口，避免隐藏重连被视作连续观测。

返回 `state` 是可序列化确认状态，按持仓保存；其中包含 `key / since / firstSampleAt / sampleAt / observedAt / count / heldBookAt / oppositeBookAt / spotAt / signalAt`。缺失或失效观测返回 `state=null`。重启、断线、换轮后不要恢复旧确认。

`decision` 可供日志与 UI 使用：

- `mode=shadow / action=observe / returnValidated=false / allocationEffect=none` 始终固定。
- `status / reasonCode / candidateExit / signalAt / earliestExecutionAt / confirmedMs / distinctObservations` 区分不可用、持有、确认中和影子候选。
- `slug / conditionId / tokenId / outcome / opening` 保存身份和基准。
- `sourceAt / receivedAt / heldBid / heldAsk / oppositeBid / twapDeviationUsd / spotDeviationUsd / spotMinusTwapUsd` 支持因果核对。
- `bookOpposesHolding / spotOpposesHolding / currentTwapDisagreesWithBook` 是描述性状态；TWAP 已转向时候选仍可保留，不能将 TWAP 已反向强行当作支持持仓。
- `terminalProxy` 明确 `official=false / usedForSignal=false`，采用已收到的 RTDS spot 分段常数积分，剩余时段假定最后已知 spot 不变；历史窗口缺失时为 `unavailable`。它不能冒充官方终点 TWAP。

```js
const eligibility = deferredTerminalQuoteEligibility({
  signal: firstConfirmedDecision, frame: laterFrame, trade, now,
});
```

该函数只验证后续报价资格，不卖出；必须新时钟可用、新帧同盘口同 token、信号后至少 1 秒，持仓侧买价/卖价完整且真实新鲜，源时间与接收时间均在延迟后，若有请求开始时间也必须在延迟后。`eligible=true` 仍只是允许计算影子深度报价，不能转换为真实成交记录。可用原有 `depthQuote` 根据实际持仓份额、当时盘口费率和真实 bid 深度计算，部分未成交余量继续等待官方核验。

建议实时记录每次 `decision`，另存第一条候选及首次合格延迟报价，关联当前 session/experiment/trade 与原帧时间；UI 显示“影子观察，不执行卖出”，保留未知与缺口数量。基准修复后积累前瞻样本，按日期留出并验证错误退出、扣费净额和占用改善后，再决定是否转主动纸面退出。

## 检查与冻结

45 项定向测试通过（纯风险模块 30 项、实时观察器 15 项）。`independent-check.json` 重新检查全部 25 笔，最后加强的时钟、缺时刻、缩短延迟与 UI 分歧标记保护没有改变任何历史候选或配对结果。

实时封装 `staged/dashboard/ray-terminal-observer.mjs` 提供 `new RayTerminalObserver({write,clock}) / ingestDiagnostic(row) / reset(reason) / sample({frame,now,owners,account}) / summary(now)`。`account` 使用现有 `engine.snapshot()` 的 `holdings` 对象。每轮 Up/Down 各建一个明确的 `hypothetical-probe`，已核实实际持仓量的 owner 另建 `owned-position`，两者分别计数；不可信数量或重复 owner 列入 `unverifiedOwners`。每个观察对象状态变化立即写，其余最多每秒写一次。spot 缓冲仅留 120 秒且最多 2048 行；连接、换轮、帧缺口会重置确认和延迟报价等待。比当前 frame 晚收到的诊断留给下一帧，不提前使用或永久丢弃。写入失败保留错误状态，不影响主交易流程。延迟报价只显示真实后续买价观察，始终 `notAnExecutedTrade=true / profitCalculated=false`。
