## 已实施

1. 将经过 OpenJS 签名及 SHA256 校验的 Node v24.19.0 复制到 归档目录/Trade/runtime-tools/node-v24.19.0-win-x64/node.exe。主后台和只读审计都使用此固定运行环境，退出或更新 ChatGPT 不需要借用其缓存目录。
2. 注册 BTC5M-Independent-Backend 和 BTC5M-Readonly-Audit 两个当前 Windows 用户任务，登录时启动；每日整天每分钟触发保活，运行中的实例忽略新触发。允许电池供电，无执行时长上限；另保留失败重试。没有更改电脑的睡眠、关机或全局电源策略。
3. 后台托管程序监控实际工作进程及 API 可达性；异常退出后拉起新进程。行情缺失、UTC 未通过或账务异常不作为“重启后跳过检查”的理由；恢复仍等待原安全检查。
4. 后台取得内核端口租约与真实 API 端口之后，才初始化账户文件。相同数据目录（包括目录别名）的第二个正常入口不能写账户；旧版本后台仍占端口时，新入口也在读写账户前拒绝启动。进程死亡后由操作系统释放租约，不使用可能误删活动锁的 PID 文件清理。
5. 用户的运行/停止、模式和暂停开仓意图，与账户状态一起原子保存。重启时保留本金、余额、库存、订单、实验和退出版本。旧快照没有运行意图时默认保持停止，不猜测开仓授权。意外退出可恢复原运行状态；手动停止保持停止；暂停开仓在启动行情前恢复。解除存储异常后也保持停止。
6. 托管进程死亡时，其工作进程通过 IPC 断开事件保存并退出，防止孤儿后台占据端口。恢复前继续核对库存与成交记录，旧模拟挂单沿用既有核对流程。
7. 页面实时流断开后自动重新取完整状态和新控制令牌；必要时以轮询显示实际后台状态，再恢复实时连接。所有自动重连仅 GET，不会自动发送开始、停止、订单或充值命令。旧流回调失效，页面重新显示时刷新状态。
8. 一键打开控制台脚本改为调用 Windows 托管后台，再打开默认浏览器；页面显示“独立后台已连接”。只读审计的原登记、源码约束和历史失败保留；没有重开已经到期的研究观察。

## 使用与边界

- 日常打开：本机控制台（历史本地服务），或双击 归档目录/Trade/打开BTC控制台.cmd。可以使用 Edge/Chrome，ChatGPT 无需一直打开。
- 平时开始、停止或暂停开仓，用控制台原按钮。“停止”只停止交易工作流，后台页面与管理服务仍可访问；后台重启也会记住停止状态。
- 若要关闭整个托管后台，运行 service/control-backend.ps1 -Action Stop。它先取得后台停止确认，再禁用并停止主任务及只读审计。若无法取得确认会报错，不把失败当作已停止。
- 再开启整个托管后台，运行 service/control-backend.ps1 -Action Start。曾手动停止策略时，仍需在控制台明确开始，不自动重新授权交易。
- 状态记录在 归档目录/Trade/service/status.json，事件记录在 supervisor-events.jsonl；每次工作进程输出在 service/logs。任务名称、执行程序和配置在 service/service-config.json。
- 这是当前用户登录范围的 Windows 托管任务。锁屏不等于注销；Windows 注销、睡眠、关机、断电或断网仍可能中断采集。需要这些情况下仍连续运行，应另行迁移到常开机器/服务器。
- 未主动更新或退出整个 ChatGPT 做破坏性验收；已核对实际后台父进程来自 Windows 任务服务而非 ChatGPT，并完成工作进程与托管进程的故障恢复演练。主服务只监听 127.0.0.1，没有开放公网。
