# CloddsBot 策略审查与优化结果

审查对象：本机下载的 `alsk1992/CloddsBot`，提交 `715fd4a6c06b4cd5bb38eee225dd09b3bc95c5e8`。本报告针对该版本，不代表远端后续版本。本次重点审查了加密策略、背离策略、做市计算与适配器、订单簿分析、机器学习、回测、套利规划和风险模块。

结论：有工程与研究价值，但没有发现可直接证明 BTC 五分钟净盈利的策略。已把可复用思路接入本地模拟控制台；默认只产生影子判断。没有安装整个原仓库依赖，也没有接入原仓库的真实交易适配器。

## 2. 已执行的优化步骤

### 步骤一：独立、可解释的策略计算

新增 `btc5m-lab/dashboard/strategy.mjs`，使用同轮连续 30 秒的数据，分别评估 Up 和 Down。

参考模型为 `75% 时间加权 EMA + 25% 买卖一档数量加权微观价格`。EMA 的时间常数为 15 秒；参考未来卖价再减去当前半个价差。该模型是假定短期价格可能回归参照值，尚未学习或校准，不能称为公平胜率模型。

候选还必须满足：TWAP 的 30 秒变化与买入方向一致、五档买卖失衡不低于 -0.2、价差不超过配置值、可见深度足够、数据新鲜、同轮且在允许开仓时段内。

### 步骤二：费用与执行过滤

- 吃单成本按实际份额遍历订单簿计算，不用中间价代替可成交均价。
- 检查买入费用、假设退出价对应的卖出费用和额外缓冲。
- 吃单情景净余量达到阈值时才提出吃单候选；只有挂单价有余量时提出挂单候选。
- 挂单期间信号失效或原挂单价不再有余量，会尝试撤单。
- 超时撤单核对后，以最新信号、最新深度、实际剩余份额和原限价重新检查；不满足则放弃吃单。
- 全局每轮最多尝试一次策略开仓，风控预算继续生效。

### 步骤三：有状态的策略退出

自动退出只管理策略自己创建的仓位，支持 Up 与 Down。入场费用进入持仓成本，退出按可见卖盘净收入判断。触发条件包含：单仓损失、买盘深度明显下降、最长持有时间、扣费退出目标、继续持有的参考价余量消失和临近结束。

退出使用限价 FAK，允许部分成交；无法成交的份额保留。损失阈值不是保证成交的止损，也不会为到期仓位虚构结算。

### 步骤四：控制台与记录

新增“策略判断”和“策略参数”。显示两侧参考价、挂单与吃单情景净余量、盘口失衡、候选或放弃理由；完整逐帧判断记录到 `<会话编号>-decisions.jsonl`。

默认 `execution=shadow`：只计算和记录。停止且无策略持仓时，可选择 `paper` 实验性模拟。旧“固定 Up 自动练习”已从控制台自动模式替换；独立命令行 `PaperDriver` 保留为历史对照基线。

参数默认：每份最小余量 $0.01、额外缓冲 $0.01、最大价差 $0.04、策略单仓损失阈值 $0.50。其他份额、最长持有时间、账户预算沿用控制台配置。这些是固定实验参数，不是搜索出的最优参数。

### 步骤五：时间顺序对照验证

新增 `review-replay.mjs`。运行 `npm run btc5m:strategy-review` 可复算本机会话行情。运行生产控制器和原固定 Up 驱动器，但不操作当前账户，不连接外网，不写入当前交易状态。

本次输入 7,650 帧、33 个轮次；有 32 个超过 5 秒的采样间隔，没有解析失败。按完整轮次时间顺序前 23 轮和后 10 轮划分，每段使用独立模拟账户。没有随机打散，没有用后段搜索参数。

## 3. 当前判定与后续准入条件

当前判定：保持影子观察，不自动升级为真实交易或“已验证策略”。历史对照仅是工程研究，不是完整实盘回测：Maker 未计成交，没有延迟、市场冲击或准确队列模型，手续费沿用现有模拟器精度，未覆盖官方结算流程；只有一个采集日且有缺口。

后续研究顺序：

1. 从影子决策和成交后价格变化中检查参考价偏差、信号存续时间及双边费用，不先扩大仓位。
2. 增加跨交易日连续数据和真实成交/队列观测，再研究 Maker 的成交概率与成交后的不利价格变化。
3. 若建设结算概率策略，先补齐可信开盘基准、到期结果和时间顺序训练/校准；不能把当前参考价直接命名为胜率。
4. 预先固定研究方案，在新的完整时间段测试净收益与风险；后段结果已被查看，再据此调参后就不能继续称它为未见样本。

本次没有执行真实订单。仓库原策略的启发已形成可运行、可检查的模块；获得正期望尚无证据。
