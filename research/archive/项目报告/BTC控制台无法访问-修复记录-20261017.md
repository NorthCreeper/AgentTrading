# BTC 控制台无法访问：补充修复

时间：2026-10-17 20:26 HKT。此次结论补充并修正早前 18:59 的独立托管验收；早前演练没有覆盖双击环境的脚本编码与控制台退出事件。

## 发现

1. 实际出现连接拒绝及 HTTP 503，后台曾中断，并非只有浏览器显示问题。主后台及只读审计的 Windows 任务先后记录 `0xC000013A`（控制台退出），自动保活拉起后仍再次退出。现有记录不能确定是谁发送了退出事件，也不能断言一定由 ChatGPT 更新引起。
2. 双击入口使用 Windows PowerShell 5.1。部分服务脚本含中文但使用没有 BOM 的 UTF-8，在这个环境中实际复现了语法解析错误，导致后台不可达时无法通过双击入口恢复。之前在 PowerShell 7 中验证入口，遗漏了此差异。
3. 旧浏览器的“无法访问”错误页没有加载控制台的重连代码，后台恢复后仍需手动刷新。浏览器安全策略拒绝读取该错误标签页，因此未通过其他浏览器表面绕过此限制，也未声称已代用户刷新成功。

## 修复

- 服务 PowerShell 脚本统一保存为带 BOM 的 UTF-8；启动入口遇错明确退出。已经用 Windows PowerShell 5 的解析器及真实桌面 CMD 入口（仅跳过打开浏览器）验证。
- 两个 Windows 任务改为本地编译的 Windows 子系统托管程序 `归档目录/Trade/service/headless-host.exe`。它持续等待 Node 进程，以 `UseShellExecute=false`、`CreateNoWindow=true` 启动并转存日志；使用关闭即清理的进程组，任务结束时清理后代，保留任务原有失败重试、登录触发与一分钟保活。
- 实际检查主托管、账户工作进程及审计的控制台窗口句柄均为零，其控制台对象不与其他应用共享。Windows 仍可能有无窗口的控制台对象，此处不将“可附着控制台对象”误称为可见窗口。
- 初始化期间，主页显示自动重试的恢复页；接口仍返回 503，避免把尚未完成的启动误报为健康。
- 新桌面入口：`归档用户目录/Desktop/打开BTC控制台.cmd`。会先检查或启动后台，再用默认浏览器打开 `http://127.0.0.1:18790/`。

Windows 机制参考：[CreateNoWindow](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.createnowindow)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。本地源代码及构建脚本均在 `归档目录/Trade/service/`。
